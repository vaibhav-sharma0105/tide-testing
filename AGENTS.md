## The One Rule That Matters Most

> **Never edit files in `src/data/`.**

`src/data/*.json` is auto-generated by `scripts/yaml-to-json.js`. Any changes there are silently overwritten on the next `npm run dev`, `npm run build`, or `npm run content:sync`. Edit `content/*.yaml` instead.

Two exceptions come from a different pipeline: the Pramaan Resource Centre files `src/data/sheets/pramaan-library.json` (data snapshot) and `src/data/pramaan-library-photos.json` (photo manifest) are written by `scripts/sync-pramaan-library.js` (via GitHub Actions), not by `yaml-to-json.js` — never hand-edit them; `content:sync` won't touch them, and `content:validate` checks the snapshot.

## How to Start

```bash
npm install          # first time only
npm run dev          # auto-syncs content, then starts dev server at localhost:5173
npm run build        # auto-syncs content, then builds to dist/
npm run content:validate   # YAML syntax, leading-slash image paths, and email / lives-impacted consistency with site.yaml
npm run lint         # ESLint (includes the jsx-no-literals CMS guard) — run in CI (deploy.yml)
npm test             # Vitest unit/component tests (17 files, 194 tests) — run in CI (deploy.yml)
```

**Run `npm run lint`, `npm test` and `npm run build` yourself before pushing — CI (`deploy.yml`) re-runs lint, `content:validate` and the unit tests before building (a failure stops the deploy), but not the Playwright e2e specs.**

## 1. Architecture

### What this project is

Production React static site for TIDE Foundation (NGO, Ahmedabad, India). 22 `<Route>`s in `src/App.jsx` (17 primary, 2 redirects, 3 system) backed by 20 lazy-loaded page components. No server, no database. Built by Vite, deployed to GitHub Pages at `/tide-testing/`.

### Tech stack

- **Vite 8 + React 19** — static bundle, `npm run build` → `dist/`
- **React Router v7** — `BrowserRouter` (clean URLs, e.g. `/pramaan/resource-centre`). GitHub Pages has no server-side rewrite, so deep links and hard reloads rely on `public/404.html` redirecting to `index.html`, which restores the original path via `history.replaceState`. **Do not assume HashRouter** — older notes in this repo's history said otherwise; `src/App.jsx` is the source of truth. A catch-all `<Route path="*" element={<NotFound />} />` is the last route in `src/App.jsx` — it only handles paths that don't match *any* route once React has mounted; the `404.html` trick above is a separate, earlier-stage mechanism for raw server-level 404s on a hard reload. `/404` is also a standalone, permanent route to the same `NotFound` page (so it can be linked/tested directly without relying on an actual unmatched path) — both must stay in sync if `NotFound` is ever replaced.
- **Tailwind CSS v3** — utility classes, design tokens in `tailwind.config.js`
- **Framer Motion 12** — page transitions, scroll animations
- **react-helmet-async** — head tags; every page except ComingSoon/NotFound renders the shared `SeoHead` component (which wraps `<Helmet>`) — don't hand-roll `<Helmet>` title/meta in new pages
- **Lucide React** — icon library

**English only.** The multilingual (EN/HI/GU) framework — i18next / react-i18next, `src/i18n/`, `content/locales/`, `LanguageSwitcher`, `src/config/features.js` (`MULTILINGUAL_ENABLED`) and the `t()` convention — has been removed; pages read the generated JSON directly (`data.x.y`). The old code is kept under the local git tag `archive/multilingual-framework` (commit `a4126d1`): `git show archive/multilingual-framework:<path>` reads a single file, `git checkout archive/multilingual-framework` browses the whole tree. `<html lang>` is a static `en` in `index.html`. Google Fonts still loads the Noto Devanagari and Gujarati families, and `font-display` / `font-body` keep them as glyph fallbacks (§3): Gujarati is needed because Pramaan resource data contains Gujarati titles; the owner chose to keep Devanagari as a fallback too.

### Data flows

There are three distinct data pipelines:

**1 — CMS pipeline (16 page YAMLs + 9 shared YAMLs → 25 JSON files)**
```
content/pages/*.yaml  ─┐   (16: pages + the Pramaan screens abl-home, pramaan-library, abl-contribute)
content/shared/*.yaml ─┤   (9: navigation, footer, common, ui, loader, error, not-found, coming-soon, site)
                        │  scripts/yaml-to-json.js  (predev/prebuild)
                        ↓
                     src/data/*.json  (auto-generated, flat, git-tracked, never edit directly)
                        ↓  import data from '../../data/page.json'
                     React page/component (reads data.* directly)
```

**2 — Site-data pipeline (`content/shared/site.yaml`)**
```
content/shared/site.yaml ──→ src/data/site.json   (via yaml-to-json; SeoHead + pages read it: SITE_URL, logo, breadcrumb parents)
content/shared/site.yaml ─┐
content/shared/llms.txt  ─┴─ scripts/siteDataPlugin.js (Vite plugin, build + dev)
                              ├─ index.html: two JSON-LD blocks (NGO, WebSite) at the `<!-- site-jsonld -->` marker, <title>, og:site_name
                              └─ /llms.txt  (template tokens {{name}} {{url}} {{email}} {{livesImpacted}} {{gradeRange}} {{foundingYear}} {{location}})
```
`siteDataPlugin.js` reads the YAML directly, so it doesn't depend on `content:sync` having run. `scripts/contentConsistency.js` + `validate-content.js` make `content:validate` fail if any email in `content/` differs from `site.yaml` `email`, or any lives-impacted total (a `NN,NNN+` figure next to "lives/people/impacted/changed" wording) differs from `livesImpacted`. `content/shared/llms.txt` is a template, not YAML, so `yaml-to-json.js` ignores it.

**3 — Pramaan Resource Centre pipeline (Sheet → snapshot, no live API) — the standard for every new Sheet integration (`docs/SHEET-INTEGRATION-PLAYBOOK.md`)**
```
Google Sheet "Contributing to Pramaan; Educators' Resource Bank (Responses)" (private, has personal data)
    ↓  apps-script/pramaan-library/Code.gs — token-gated export/fetchImage only; consented rows (Q, R, S = Yes); never columns L–P
.github/workflows/sync-pramaan-library.yml → scripts/sync-pramaan-library.js (+ scripts/lib/library-snapshot.js, scripts/lib/snapshot-core.js)
    ↓  commits src/data/sheets/pramaan-library.json + src/data/pramaan-library-photos.json + public/assets/images/pramaan-library/
PramaanLibrary / PramaanLibraryDetail (/pramaan/resource-centre) and AblHome's counts (/pramaan) — import the snapshot at build time
```
No page reads a Sheet in the browser. (The former live read — `useABLData` → Apps Script — was retired on 2026-11-19; archived in git tag `archive/pramaan-live-read`.) See §8.

### Routing

`src/App.jsx` registers 22 `<Route>`s (20 lazy-loaded page components). `BrowserRouter` (`basename={import.meta.env.BASE_URL}`) wraps everything — clean URLs, no `#`. `Layout` (skip link + Header + Footer) wraps every route; each page chunk is `lazy()`-loaded behind a `Suspense` fallback that shows `CreativeLoader` only after 200 ms (`useDelayedVisible`). `src/components/ErrorBoundary.jsx` wraps the whole app (outside the Router and `HelmetProvider`): on a render crash it shows a friendly screen (heading/body/button labels from `content/shared/error.yaml`, a reload button and a plain `<a>` home link) and logs the error to the console; the error message and stack are rendered only when `import.meta.env.DEV`. `MotionConfig reducedMotion="user"` makes all Framer animations respect the OS setting.

| Group | Count | Routes |
|---|---|---|
| Primary | 17 | `/`, `/about/{why-tide,past-programs,our-team,our-partners,publications}`, `/education-for-harmony`, `/education-for-harmony/mccx`, `/education-for-harmony/social-changemakers` (not in any menu), `/pramaan`, `/pramaan/resource-centre`, `/pramaan/resource-centre/:id`, `/pramaan/contribute`, `/get-involved/{volunteer,donate}`, `/thrive`, `/contact` |
| Redirect | 2 | `/pramaan-library`, `/pramaan-library/:id` → `/pramaan/resource-centre(/:id)` (the Resource Centre's former address; `LibraryRedirect` keeps the query string) |
| System | 3 | `/coming-soon`, `/404`, `*` (the last two both render `NotFound`) |

The 16 routes that predated the restructure (`/about/our-results`, `/projects/*`, `/get-involved/{work-with-us,mccx}`, `/resources/*`) were **removed outright** by owner decision, with no redirects: their pages, YAMLs and generated JSON are gone, and those URLs now fall through to `*` and render `NotFound`. `src/test/routing/removedRoutes.test.jsx` renders the real `<App />` at each removed path and asserts the NotFound page (plus a control that a live route does not). `OrganizeMCCx` is served only at `/education-for-harmony/mccx`. `git checkout a4126d1 -- <path>` recovers the old files.

### Colour tokens

| Tailwind class | Hex | Usage |
|---|---|---|
| `text-primary` / `bg-primary` | `#1E6BAA` | Buttons, links, heading accents |
| `bg-primary-mid` | `#2E85C7` | Gradient buttons (paired with `primary-dark`) |

| `bg-accent-dark` | `#D97706` | Gradient buttons, hover states |
| `bg-navy` | `#0D2137` | Dark section/card backgrounds (Footer, EFH, WhyTide vision, Volunteer dark sections). **Not** `PageHero` — that banner is the literal `bg-[#1c314d]` |
| `text-tide-text` | `#0D1F3C` | Body copy |
| `text-tide-muted` | `#5A6A7E` | Secondary labels, captions — passes 4.5:1 on `tide-bg`/white, but NOT on `bg-primary-light` (4.49:1, borderline) |
| `text-tide-mutedOnLight` | `#4D5C6F` | Same role as `tide-muted`, but for text sitting on `bg-primary-light` or `bg-tide-border` specifically |
| `bg-tide-bg` | `#FDFCF9` | Page section backgrounds |
| `bg-tide-subtle` | `#F0EDE8` | Input fields, card inner areas |
| `border-tide-border` | `#E2DDD7` | Card and input borders |

Full token map (incl. `deeper`/all shade variants): `tailwind.config.js`. If this table ever disagrees with that file, trust `tailwind.config.js`. The `<meta name="theme-color">` in `index.html` is `#1E6BAA` (same as `primary`).

**Accessibility note on `text-accent` (2026-06-22 audit):** `#F59E0B` is too light to use as foreground text/icon color on a light background — only 2.09:1 on `tide-bg`, 2.15:1 on white, failing even the relaxed 3:1 "large text" threshold. It works well (5.9–7.6:1) on dark backdrops (navy footer, dark hero overlays, `bg-navy` cards) precisely because it's light — use `text-accent-deeper` instead whenever accent-colored text/icons sit on a light background. Same logic applies to the `text-tide-muted` → `text-tide-mutedOnLight` swap on light-blue chip backgrounds. Don't pattern-match the wrong fix from a different background context — check what's actually behind the text first.

### Typography

| Tailwind class | Font | Usage |
|---|---|---|
| `font-display` | Playfair Display | Headings h1–h3, card names, section titles |
| `font-body` | Plus Jakarta Sans | All body text, labels, inputs, buttons |

`font-display` and `font-body` are single combined stacks in `tailwind.config.js` (Playfair/Plus Jakarta Sans first, then the Noto Devanagari and Gujarati families as glyph fallbacks), and `index.html` loads those Noto families from Google Fonts. Nothing switches fonts by language, there is no CSS keyed on `<html lang>`, and `lang` stays `en`.

### Keyboard focus ring

The global `:focus-visible` rule in `src/index.css` draws a 2px outline in the brand blue (`theme('colors.primary.DEFAULT')`, `#1E6BAA`) with a 2px offset, plus a 2px white `box-shadow` band, so the ring stays visible on the dark navy sections (brand blue alone is only about 2.9:1 there). A few components (e.g. the `PhotoStrip` tiles and the Resource Centre filters) opt out with `focus:outline-none` and draw their own Tailwind `ring` instead.

### Shadows and spacing

| Class | Usage |
|---|---|

| `shadow-card-hover` | Card on hover |
| `shadow-nav` | Fixed header when scrolled |

### Scroll animation pattern

Page sections share the presets in `src/utils/motionPresets.js` instead of redefining a local `fadeUp`:
```jsx
import { fadeUp, makeFadeUp } from '../utils/motionPresets'

<motion.div {...fadeUp()} />            // default: y 24, 0.6s, viewport { once: true }
<motion.div {...fadeUp(0.1)} />         // argument = delay (seconds); stagger with i * 0.08
const fadeUp = makeFadeUp({ y: 20, duration: 0.55, margin: '-60px' })  // page-specific variant
```
`makeFadeUp({ y = 24, duration = 0.6, margin })` returns `(delay = 0) => ({ initial, whileInView, viewport, transition })` with ease `[0.4, 0, 0.2, 1]`. `Card`, `SectionHeader` and a few one-off blocks still inline their own `initial`/`whileInView`/`viewport` props — same shape, `once: true`, ease `[0.4, 0, 0.2, 1]`. `useScrollAnimation` is only used by `AnimatedCounter`.

### Non-serialisable values (Tailwind + icons in YAML)

Tailwind classes must appear as complete strings in source — never construct them dynamically. Icons are React components and can't be JSON. The pattern:

1. Store a key string in YAML: `iconKey: "BookOpen"`, `colorKey: "blue"`
2. Define a lookup map in the component:

```jsx
const ICONS = { BookOpen: <BookOpen className="w-5 h-5" />, Users: <Users className="w-5 h-5" /> }
const COLOR_MAP = {
  blue:    'bg-blue-50 text-blue-700 border-blue-200',
  emerald: 'bg-emerald-50 text-emerald-700 border-emerald-200',
}
// Usage: {ICONS[item.iconKey]}   COLOR_MAP[item.colorKey]
```

## 4. Component API

### Button

```jsx
<Button
  variant="primary"         // primary | secondary | accent | ghost | white
  size="md"                 // sm | md | lg
  to="/internal/path"       // renders as <Link> (React Router)
  href="https://external"   // renders as <a>
  external                  // with href: adds target="_blank" rel="noopener noreferrer"
  className="mt-4"
>Label</Button>
```

With neither `to` nor `href` it renders a `<button>`; extra props are spread onto the element. `href` alone does **not** open a new tab — pass `external` for that.

### PageHero

```jsx
<PageHero
  badge="Section · Subsection"    // small label above the title
  title="Page Title"              // h1
  subtitle="Optional description"
>{/* optional children, rendered under the subtitle */}</PageHero>
```

Props are exactly `{ badge, badgeClassName, title, subtitle, children, aside }`; `aside` is an optional node placed to the right of the text on large screens (below it on small ones), used by `/pramaan` for the promo video. `badgeClassName` replaces the badge's default `bg-white/15 text-white/90 border-white/25` colour classes; the resource detail page passes the type's `heroBadge` so the banner pill wears the type colour. Background is the literal `bg-[#1c314d]` plus a texture image. There is no `gradient` prop (it used to be passed, and ignored, by 10 pages; those were removed) — don't add one. The header is fixed and transparent with white text over the hero, so inner pages need a `PageHero` (or an equivalent dark top section) first, before `<AblNavBar>` or any content.

### SeoHead

```jsx
<SeoHead
  title={data.meta.seoTitle}
  description={data.meta.seoDescription}
  path="/get-involved/volunteer"           // required; canonical = site.url (site.yaml) + path
  breadcrumbs={[
    { name: site.breadcrumbs.home, path: '/' },
    { name: site.breadcrumbs.getInvolved },                        // no path → no `item` in the JSON-LD
    { name: data.meta.breadcrumbName, path: '/get-involved/volunteer' },
  ]}                                        // import site from '../../data/site.json'
  noindex                                   // optional, default false
  ogImagePath="/some/image.png"             // optional; appended to window.location.origin WITHOUT the base path
/>
```

Every page except `ComingSoon` and `NotFound` (which use `<Helmet>` directly with `noindex`) renders `SeoHead`. It emits title, description, canonical, og:*, twitter:*, optional `robots noindex`, and a BreadcrumbList JSON-LD block (a breadcrumb without `path` omits `item`). `SITE_URL` and the default og:image (`site.logo` under `BASE_URL`) come from `site.json`. Breadcrumb names are not hardcoded: parent steps come from `content/shared/site.yaml` `breadcrumbs.*` and each page's own last step is `meta.breadcrumbName` in its YAML (`PramaanLibraryDetail` uses the resource name). Head tags are injected client-side only (no prerender); `index.html` has no static description/canonical, but its `<title>`, `og:site_name` and the NGO/WebSite JSON-LD are generated from `site.yaml` by `scripts/siteDataPlugin.js`.

### AnimatedCounter

```jsx
<AnimatedCounter
```

### Lightbox (gallery — for non-ABL pages)

`Lightbox` is a controlled, presentational component — the page owns the open/index state (usually through `useLightbox(count)`):

```jsx
import { AnimatePresence } from 'framer-motion'
import { useLightbox } from '../hooks/useLightbox'
import Lightbox from '../components/ui/Lightbox'

const images = [{ src: 'assets/photo.jpg', label: 'Caption' }]   // or plain strings
const lb = useLightbox(images.length)        // count is REQUIRED
// Open: lb.openLightbox(index)

<AnimatePresence>
  {lb.isLightboxOpen && (
    <Lightbox
      images={images}                         // (string | { src, alt?, label? })[]
      currentIndex={lb.lightboxIndex}
      onClose={lb.closeLightbox}
      onPrev={lb.prevLightbox}
      onNext={lb.nextLightbox}
      onGoTo={lb.openLightbox}                // optional; without it, clicking a dot CLOSES the lightbox
    />
  )}
</AnimatePresence>
```

`item.alt || item.label` is used as the image `alt` and the dialog's `aria-label`; **no caption is rendered under the image anywhere on the site** (owner decision) — don't add one. Pass `translucent` for a see-through, blurred backdrop (the `/pramaan` gallery) instead of the near-opaque default. The tint and blur ease in on their own layer and the controls fade separately: **never fade a parent that holds a `backdrop-filter`** (it pops at full strength on the first frame), and keep the picture `relative z-[1]` so the positioned backdrop does not paint over, and blur, it. `Lightbox` applies `imgSrc()` to every `src` itself — **do not pre-apply `imgSrc`** (see §11). Escape closes, ←/→ navigate, body scroll is locked (`useModalBehavior`), focus is trapped (`useFocusTrap`), and the dot strip shows for 2–20 images. Its aria-labels come from `content/shared/ui.yaml` (`lightbox.*`).

For a click-to-zoom photo grid, pair `useLightbox(count)` with `<AnimatePresence>{isLightboxOpen && <Lightbox …/>}</AnimatePresence>` — `src/components/abl/PhotoStrip.jsx` (the `/pramaan` photo strip) is the working example. For multiple galleries on one page, use separate `useLightbox(count)` instances with distinct names.

### VideoLightbox (full-screen video overlay)

```jsx
const [videoOpen, setVideoOpen] = useState(false)

<VideoLightbox
```

Same backdrop/close conventions as `ImageLightbox` (ESC, backdrop click, close button) but renders a landscape 16:9 iframe instead of an `<img>`. `translucent` swaps the dark backdrop for the blurred see-through one and widens the player (used by `PromoVideo` on `/pramaan` and by `PramaanLibraryDetail`, whose player URL comes from `getVideoEmbedUrl` in `src/utils/videoLinks.js`). Labels: `ui.yaml` → `mediaLightbox.*`.

### DriveImage

```jsx
<DriveImage
```

## 5. Hook Reference

### useScrollAnimation

```js
const [ref, isVisible] = useScrollAnimation({ threshold: 0.15, rootMargin: '0px 0px -60px 0px', once: true })
// Attach ref to any DOM element
// isVisible flips to true when the element enters the viewport and never flips back
```

Only `AnimatedCounter` uses it (on the Pramaan home page and Education for Harmony); all other scroll animation is Framer `whileInView`.

### useLightbox

```js
const { isLightboxOpen, lightboxIndex, openLightbox, closeLightbox, prevLightbox, nextLightbox }
  = useLightbox(count)          // count = number of images — REQUIRED
// openLightbox(index) — open at a specific image
// prevLightbox() / nextLightbox() — cycle with wrap-around (modulo count)
```

`lightboxIndex` is `null` while closed. Calling it without `count` makes prev/next produce `NaN`. `PhotoStrip.jsx` is the working example.

### useModalBehavior

```js
useModalBehavior({ active = true, onClose, onKeyExtra, target = 'document' })
```

Shared overlay behaviour: while `active` is truthy, Escape calls `onClose`, any keydown is also forwarded to `onKeyExtra(e)` (e.g. Lightbox arrow keys), and `document.body` scrolling is locked; cleanup resets `body.style.overflow` to `''`. `target` (`'window'` | `'document'`) chooses where the listener lives (Lightbox uses `window`, `ImageLightbox`/`VideoLightbox` use `document`). Keep `onClose`/`onKeyExtra` referentially stable (`useCallback`) — a new identity re-registers the listener. Used by `Lightbox`, `ImageLightbox`, `VideoLightbox`; pair it with `useFocusTrap`, declared first.

### useFocusTrap

```js
const containerRef = useFocusTrap(active = true)   // attach containerRef to the dialog element
```

On activation stores `document.activeElement`, focuses the first focusable child (selector `button, a[href], iframe, [tabindex]:not([tabindex="-1"])`), traps Tab/Shift+Tab inside the container, and restores focus on deactivation/unmount (with `preventScroll`, so closing a dialog never scrolls or glides the page). For a conditionally *mounted* dialog, the default `true` is right; for an always-mounted one pass the open condition.

### useDelayedVisible

```js
const show = useDelayedVisible(active, delayMs = 200)
```

True only if `active` stays true for longer than `delayMs` — gates loading UI so fast loads never flash it (used for the route `Suspense` fallback).

## 6. Utility Reference

### imgSrc.js

```js
import { imgSrc } from '../utils/imgSrc'

imgSrc('/assets/images/foo.jpg')   // → BASE_URL + 'assets/images/foo.jpg'
imgSrc('assets/images/foo.jpg')    // → same
imgSrc('https://…')                // → returned as-is (also data: URLs)

```

Use it for any image path that comes from YAML/JSON so it works on both `/` (dev) and `/tide-testing/` (GitHub Pages). **It is not idempotent** — see the gotcha in §11. Some files (Home, OurPartners, Header, Footer, PageHero, SeoHead, ErrorBoundary) instead build `${import.meta.env.BASE_URL}${path}` by hand; that only works because `yaml-to-json.js` strips the leading `/` from `/assets/...` values.

### imagePlaceholder.js

`installImagePlaceholder(doc = document)` is called once in `src/main.jsx` before the app renders. It adds one capturing `error` listener on the document (image `error` events don't bubble) and, for any `<img>` that fails to load, drops `srcset` and sets `src` to the placeholder: `imgSrc(site.placeholderImage)`, where `placeholderImage` is `/assets/images/shared/placeholder.svg` in `content/shared/site.yaml`. An image opts out with the `data-no-placeholder` attribute (`abl/DriveImage.jsx` does, because it draws its own `<BookOpen>` fallback); the placeholder's own URL is skipped so a missing placeholder can't loop. It returns an uninstall function (used by `src/test/utils/imagePlaceholder.test.js`). Because it's global, don't add per-image `onError` handlers for the same purpose.

### motionPresets.js

`makeFadeUp({ y = 24, duration = 0.6, margin })` → `(delay = 0) => motionProps`, and the default-parameter instance `fadeUp`. Spread onto a `motion.*` element: `<motion.div {...fadeUp(0.1)}>`. See §3 "Scroll animation pattern".

### config/abl.js and config/library.js

`config/abl.js` exports the resource-type tables for the Pramaan screens: `TAB_STYLE_MAP` and `getTabStyle(tab)` (returns the map entry, falling back to `_default` for unknown types), and `TYPE_COLORS` / `getTypeColors(tab)`: the single class palette per colour name (`badge`, `eyebrow`, `solid`, `soft`, `tint`, `selectedTile`, `poster`, `heroBadge`, `tileHover`, `cardHover`, `titleHover`) that `ResourceTypeBadge`, the `/pramaan` type cards and the Resource Centre's badges, filter tiles and cards all read, so a type is the same colour everywhere. A new colour name needs an entry there (written out in full, for Tailwind). See §8 for how to add a type.

`config/library.js` exports `LIBRARY_PAGE_SIZE` (9) and `libraryTypeKey(type)` / `libraryTypeColors(type)`: a Resource Centre row's free-typed type ("Kit", "worksheets") mapped to the Pramaan type key of the same name (case-insensitive, trailing "s" ignored), or `null` → neutral grey.

`applyLibraryFilters(resources, filters)` (subject / type / owner by normalised key, grades any-of, search in name + concept + description, then the chosen sort), `facetOptions(resources, filters)` (faceted counts), `optionsFor`, `orderFilterOptions`, `typeParamKey(value, resources)` (the `?type=` value as a filter key; also accepts the former Resource Centre's names such as `Kits`, so old links still filter), `linkParts(text)`, `LIBRARY_GRADES` (Foundational + Grade 1–5, the grade filter list) and `gradeLabel`. ## 7. CMS Pipeline

### Commands

```bash
npm run content:sync       # YAML → JSON (also runs automatically via predev/prebuild)
npm run content:validate   # YAML syntax + image path checks + site.yaml consistency (see below)
npm run content:bootstrap  # Writes starter shared/navigation.yaml + footer.yaml ONLY if absent. Does not touch pages; rarely needed.
```

### What `scripts/yaml-to-json.js` does

- Walks `content/pages/**` and `content/shared/**` (`*.yml|*.yaml`) and writes `src/data/<basename>.json`. The output is **flat**: directory names are dropped, so two YAMLs with the same basename (e.g. one in `pages/`, one in `shared/`) silently overwrite each other. It is run from the repo root (paths resolve from `process.cwd()`).
- Any string value starting with `/assets/` has its leading `/` stripped (so `/assets/images/x.jpg` → `assets/images/x.jpg`); other leading-slash values (routes, `mailto:`) are untouched.
- Fails fast on invalid YAML (non-zero exit → blocks `dev`/`build`, and CI). It does **not** delete JSON for a YAML you removed (the stale file stays importable), and has no schema/required-field checks. Only `*.yml|*.yaml` are read, so `content/shared/llms.txt` is ignored.
- `src/data/*.json` is committed, but regenerated on every dev/build — never hand-edit it.

### What `scripts/validate-content.js` checks (and doesn't)

Walks all of `content/`; a YAML parse error is an error (exit 1), a missing image is only a warning (exit 0). Images are checked only for values under the keys `photo, src, logo, coverImage, image, poster, img, heroPhoto, mainPhoto, diagramPhoto, backgroundImage, donorPoster` **and** only when the value starts with `/` and isn't http(s). So values without a leading slash, other keys (e.g. `photo1`/`photo2`), and image arrays of bare strings are not checked. It does not check hrefs/routes.

**Consistency errors (exit 1):** via `scripts/contentConsistency.js`, every string in every YAML (plus the `llms.txt` template) is scanned. Any email address that differs from `site.yaml` `email` is an error, and so is any lives-impacted total (a `NN,NNN+` / `NNNNN+` figure in the same sentence as "lives / people / impacted / changed", or a bare figure whose sibling fields say so) that differs from `site.yaml` `livesImpacted`. Other metrics such as "15,000+ students" are deliberately not flagged. To change the email or the figure, edit `site.yaml` and then every page string that quotes it. CI (`deploy.yml`) runs the validator before building, so an error stops the deploy. It also checks the Resource Centre snapshot (`checkLibrarySnapshot()`: shape, unique ids, allowlisted fields only, no e-mail addresses, `meta.total`, photo manifest paths/files) and `abl-contribute.yaml` `formUrl` (empty → warning; anything but a Google Forms link → error).

### Lint guard (`react/jsx-no-literals`)

`eslint.config.js` makes `react/jsx-no-literals` an **error** in `src/pages/**/*.jsx` and `src/components/**/*.jsx` (`noStrings: false`, `ignoreProps: true`; allowed bare strings are punctuation/glyphs: `— – · → ↗ … | / - : . , & + ( ) % " ' “ ” ’`). Text typed straight into JSX therefore fails `npm run lint`. What it does **not** catch: string-literal props and attributes (`aria-label`, `alt`, `title`, …) and text in `{'…'}` expressions — review those by hand. JSON-LD and breadcrumb names are no longer hardcoded (they come from `site.yaml` / `meta.breadcrumbName`). CI runs lint too (a failure stops the deploy); run it locally first. Also see `.claude/skills/cms-integrity/SKILL.md`.

### Image paths in YAML

Images live in `public/assets/`. Both spellings work because the sync script strips a leading `/` from `/assets/…` values, and the repo overwhelmingly uses the leading-slash form (≈165 values vs 5 without):
```yaml

photo: assets/team/jane-smith.jpg    # also works, but is invisible to the validator
```
The one hard rule: components must pass YAML image values through `imgSrc()` (or prefix `import.meta.env.BASE_URL`), never use them raw (§6, §11). `CONTENT-GUIDE.md` tells editors the leading-slash form.

## 11. Gotchas & Constraints

### BrowserRouter on a static host (GitHub Pages)

All internal links must use `<Link to="...">` from React Router, never `<a href="...">`:
```jsx
// Wrong
<a href="/about/our-team">Team</a>

// Correct
<Link to="/about/our-team">Team</Link>
```

Plain `href` triggers a real page navigation instead of client-side routing — slower, and on first load `index.html`'s inline script has to run the redirect-restoration logic again.

GitHub Pages serves static files only — there's no server-side rewrite for deep routes. The site uses the standard `404.html`-redirect trick: a hard reload or direct link to e.g. `/pramaan/resource-centre?type=worksheet` gets served `public/404.html`, which redirects to `/?/pramaan/resource-centre&type=worksheet`; `index.html`'s inline script then decodes that back into the real path via `history.replaceState` before React mounts. **If you touch either script, verify the query-string case specifically** — a previous bug here joined the restored path and query with `&` instead of `?`, which silently produced a malformed URL (no error, just a blank page) for any route with query params on a hard reload.

### `imgSrc()` is not idempotent

`imgSrc(path)` prepends `BASE_URL` to anything that isn't already `http(s):`/`data:`. On GitHub Pages `BASE_URL` is `/tide-testing/`, so applying it to an already-resolved path yields `/tide-testing/tide-testing/...` (a 404). In dev `BASE_URL` is `/`, which hides the bug completely.

- `Lightbox` applies `imgSrc` to every image `src` themselves — pass **raw YAML paths** into them.
- To check a change: `GITHUB_ACTIONS=true npm run build && npm run preview`, then open `/tide-testing/…`.

### Tailwind dynamic class construction is forbidden

Tailwind scans source files for complete class strings. Constructing them at runtime means the class won't be in the CSS bundle:
```jsx
// Wrong — Tailwind won't include bg-blue-50 or bg-emerald-50
const cls = `bg-${color}-50`

// Correct — full strings appear literally
const COLOR_MAP = { blue: 'bg-blue-50 text-blue-700', emerald: 'bg-emerald-50 text-emerald-700' }
const cls = COLOR_MAP[color]
```

This is why all colour maps in components use lookup tables. Tailwind's `content` globs only `index.html` and `src/**`.

### Pramaan data is built in, not fetched

The Resource Centre and the `/pramaan` counts import `src/data/sheets/pramaan-library.json` at build time. A Sheet edit reaches the site only through the sync → commit → deploy (minutes, or the next 6-hourly run) — there is no runtime request and no loading state to handle. Don't reintroduce a browser-side Sheet read (the retired `useABLData` pattern; see `docs/SHEET-INTEGRATION-PLAYBOOK.md`).

### A modal's backdrop, scrollbar and caption

- A blurred backdrop is its own layer, faded on its own (see `Lightbox` in §4): fading the parent that holds a `backdrop-filter` makes the blur pop, and a positioned backdrop paints over a non-positioned picture, so the picture needs `relative z-[1]`. If a viewer's photo looks blurry, check this first.
- `html { scrollbar-gutter: stable }` (`src/index.css`) stops the page shifting sideways when a modal locks body scrolling.
- Image previews show **no caption** anywhere on the site.

### The photo strip tells a tap from a drag

`PhotoStrip` captures the pointer on the strip, so a click lands on the container, not the photo. A tap (under ~6px of movement) is detected in `pointerup` from the tile index recorded at `pointerdown`; each photo is also a focusable button for the keyboard, and only keyboard focus (`:focus-visible`) slides the photo to the middle, so a mouse click never makes the photo jump before the viewer opens.

### Header overflow for flyout menus

The `Dropdown` component in `Header.jsx` uses `overflow-visible` so that flyout submenus can render outside the dropdown container. Do not add `overflow-hidden` to the dropdown wrapper or the flyout will be clipped. The header is `position: fixed` at 70px height; `AblNavBar` (`top-[70px]`) and the Resource Centre sidebar (`top-[130px]`) are positioned against that, so changing the header height breaks both.

### VITE_ prefix required for browser env vars

```bash
MY_SECRET=foo          # NOT visible to browser code
VITE_MY_SECRET=foo     # visible via import.meta.env.VITE_MY_SECRET
```

### Image paths in YAML

Either `/assets/hero.jpg` or `assets/hero.jpg` works (the sync script strips the leading `/` from `/assets/…`); the repo's dominant style is the leading-slash form, and only that form is checked by `content:validate`. What breaks things is using the value raw without `imgSrc()` / `BASE_URL` — see §6.

### Multiple galleries on the same page

Use one `useLightbox(count)` instance per gallery with distinct names (the count argument is required):
```jsx
const first  = useLightbox(data.galleryA.images.length)
const second = useLightbox(data.galleryB.images.length)
```


### No hardcoded visible text (CMS convention + lint guard)

Never type English into JSX — that bypasses the CMS and makes the text uneditable:

```jsx
// ✓ Correct — CMS-editable
<h1>{data.hero.title}</h1>
<p>{common.step}</p>                                       // shared micro-copy → content/shared/common.yaml

// ✗ Wrong — hardcoded, CMS cannot update it
<p>Click any image to view full screen.</p>             // also fails `npm run lint`
```

- Shared micro-copy goes in `content/shared/common.yaml` (page-agnostic hints/labels such as `step`, `viewLinkedIn`) and component chrome in `content/shared/ui.yaml` (Lightbox and Pramaan photo/video viewer labels). Component-specific text goes in the page/screen YAML (e.g. `pramaan-library.yaml`).
- `react/jsx-no-literals` is an **error** for `src/pages/**` and `src/components/**` (see §7), so bare JSX text fails `npm run lint`. It doesn't see string props or attributes (`aria-label`, `alt`, …), so review those by hand.
- CI runs lint (a failure stops the deploy), but run `npm run lint` before pushing.

### The e-mail and lives-impacted figure live in `site.yaml`

The contact email is `tidefoundation@gmail.com` and the lives-impacted total is `52,500+` everywhere (owner decision). The single source is `content/shared/site.yaml` (`email`, `livesImpacted`); `npm run content:validate` errors on any other email or lives-impacted total in `content/`. Other metrics (e.g. "15,000+ students") are intentionally not flagged.

### Don't put a literal `<title>` in an HTML comment in `index.html`

`scripts/siteDataPlugin.js` fills the page title with `html.replace(/<title>[\s\S]*?<\/title>/, …)`, which replaces the first match — a commented-out `<title>…</title>` earlier in the file would be rewritten instead of the real tag. Likewise keep the `<!-- site-jsonld -->` marker (the plugin throws if it is missing) and don't hand-write JSON-LD in `index.html`.

### Generated files are committed

`src/data/*.json` is generated and git-tracked; it is re-written on every `dev`/`build`. A manual `git add content/` without re-running the sync leaves the committed JSON behind until CI/the next local run regenerates it.

### AnimatePresence requires key prop

Exit animations on conditionally-rendered elements only fire when the child has a stable `key`:
```jsx
<AnimatePresence>
  {isOpen && <motion.div key="drawer" initial={{ x: '-100%' }} ...>...</motion.div>}
</AnimatePresence>
```
