## The One Rule That Matters Most

> **Never edit files in `src/data/`.**

`src/data/*.json` is auto-generated by `scripts/yaml-to-json.js`. Any changes there are silently overwritten on the next `npm run dev`, `npm run build`, or `npm run content:sync`. Edit `content/*.yaml` instead.

Two exceptions come from a different pipeline: the Pramaan Resource Centre files `src/data/sheets/pramaan-library.json` (data snapshot) and `src/data/pramaan-library-photos.json` (photo manifest) are written by `scripts/sync-pramaan-library.js` (via GitHub Actions), not by `yaml-to-json.js` — never hand-edit them; `content:sync` won't touch them, and `content:validate` checks the snapshot.

## How to Start

```bash
npm install          # first time only
npm run dev          # auto-syncs content, then starts dev server at localhost:5173
npm run build        # auto-syncs content, then builds to dist/
npm run content:validate   # YAML syntax, every local file path, the four Sheet snapshots, formUrl, email / lives-impacted consistency
npm run lint         # ESLint (includes the jsx-no-literals CMS guard) — run in CI (deploy.yml)
npm test             # Vitest unit/component tests (46 files, 524 tests) — run in CI (deploy.yml)
npm run test:e2e     # Playwright against the dev server (local only)
npm run test:e2e:site  # Playwright against the built base-path dist/ (Chromium) — run in CI after the build
```

**Run `npm run lint`, `npm test` and `npm run build` yourself before pushing — CI (`deploy.yml`) re-runs lint, `content:validate` and the unit tests before building, then `check:dist` and the built-site e2e (`test:e2e:site`); a failure stops the deploy. The dev-server specs (`npm run test:e2e`) and the visual baselines are local only.**

## 1. Architecture

### What this project is

Production React static site for TIDE Foundation (NGO, Ahmedabad, India). 24 routes in `src/routes.js` (18 primary, 3 redirects, 3 system; `src/App.jsx` maps them to `<Route>`s) backed by 22 lazy-loaded page components. No server, no database. Built by Vite, every public page prerendered to HTML (`scripts/prerender.mjs`), deployed to GitHub Pages at `/tide-testing/`.

### Tech stack

- **Vite 8 + React 19** — static bundle, `npm run build` → `dist/`
- **React Router v7** — `BrowserRouter` (clean URLs, e.g. `/pramaan/resource-centre`). GitHub Pages has no server-side rewrite; since 2026-11-24 every public route is a prerendered file (`about/why-tide.html`), and `dist/404.html` (the prerendered NotFound page, generated — there is no `public/404.html`) is served with HTTP 404 for any other address, after which the app renders whatever route matches (§11). **Do not assume HashRouter** — older notes in this repo's history said otherwise; `src/routes.js` + `src/App.jsx` are the source of truth. A catch-all `['*', NotFound]` is the last entry in `src/routes.js` — it handles paths that don't match *any* route once React has mounted. `/404` is also a standalone, permanent route to the same `NotFound` page (so it can be linked/tested directly without relying on an actual unmatched path) — both must stay in sync if `NotFound` is ever replaced.
- **Tailwind CSS v3** — utility classes, design tokens in `tailwind.config.js`
- **Framer Motion 12** — page transitions, scroll animations
- **react-helmet-async** — head tags; every page except ComingSoon/NotFound (and the two redirect components, which render no head tags) renders the shared `SeoHead` component (which wraps `<Helmet>`) — don't hand-roll `<Helmet>` title/meta in new pages
- **Lucide React** — icon library

**English only.** The multilingual (EN/HI/GU) framework — i18next / react-i18next, `src/i18n/`, `content/locales/`, `LanguageSwitcher`, `src/config/features.js` (`MULTILINGUAL_ENABLED`) and the `t()` convention — has been removed; pages read the generated JSON directly (`data.x.y`). The old code is kept under the local git tag `archive/multilingual-framework` (commit `a4126d1`): `git show archive/multilingual-framework:<path>` reads a single file, `git checkout archive/multilingual-framework` browses the whole tree. `<html lang>` is a static `en` in `index.html`. Google Fonts still loads the Noto Devanagari and Gujarati families, and `font-display` / `font-body` keep them as glyph fallbacks (§3): Gujarati is needed because Pramaan resource data contains Gujarati titles; the owner chose to keep Devanagari as a fallback too.

### Data flows

There are six data pipelines (the CMS, the site data, and four Sheet snapshots):

**1 — CMS pipeline (17 page YAMLs + 9 shared YAMLs → 26 JSON files)**
```
content/pages/*.yaml  ─┐   (17: pages + the Pramaan screens abl-home, pramaan-library, abl-contribute)
content/shared/*.yaml ─┤   (9: navigation, footer, common, ui, loader, error, not-found, coming-soon, site)
                        │  scripts/yaml-to-json.js  (predev/prebuild)
                        ↓
                     src/data/*.json  (auto-generated, flat, git-tracked, never edit directly)
                        ↓  import data from '../../data/page.json'
                     React page/component (reads data.* directly)
```

**2 — Site-data pipeline (`content/shared/site.yaml`)**
```
content/shared/site.yaml ──→ src/data/site.json   (via yaml-to-json; SeoHead + pages read it: SITE_URL, logo, breadcrumb parents)
content/shared/site.yaml ─┐
content/shared/llms.txt  ─┴─ scripts/siteDataPlugin.js (Vite plugin, build + dev; + src/config/siteRoutes.js, the Resource Centre snapshot, footer.yaml social, contact.yaml address)
                              ├─ index.html: two JSON-LD blocks (NGO, WebSite) at the `<!-- site-jsonld -->` marker, <title>, og:site_name
                              ├─ /llms.txt  (template tokens {{name}} {{url}} {{email}} {{livesImpacted}} {{gradeRange}} {{foundingYear}} {{location}} {{pages}} — {{pages}} = one line per sitemap page: breadcrumb name + meta.seoDescription)
                              ├─ /robots.txt (site.yaml crawlers + url)
                              └─ /sitemap.xml (siteRoutes.js PRIMARY_ROUTES minus sitemap:false + one URL per Resource Centre row; <lastmod> = last git commit of the page's sources, left out in a shallow clone)
```
`siteDataPlugin.js` reads the YAML directly, so it doesn't depend on `content:sync` having run. `scripts/contentConsistency.js` + `validate-content.js` make `content:validate` fail if any email in `content/` differs from `site.yaml` `email`, or any lives-impacted total (a `NN,NNN+` figure next to "lives/people/impacted/changed" wording) differs from `livesImpacted`. `content/shared/llms.txt` is a template, not YAML, so `yaml-to-json.js` ignores it.

**3 — Pramaan Resource Centre pipeline (Sheet → snapshot, no live API) — the standard for every new Sheet integration (`docs/SHEET-INTEGRATION-PLAYBOOK.md`)**
```
Google Sheet "Contributing to Pramaan; Educators' Resource Bank (Responses)" (private, has personal data)
    ↓  apps-script/pramaan-library/Code.gs — token-gated export/fetchImage only; consented rows (Q, R, S = Yes); never columns L–P
.github/workflows/sync-pramaan-library.yml → scripts/sync-pramaan-library.js (+ scripts/lib/library-snapshot.js, scripts/lib/snapshot-core.js, scripts/lib/sync-runner.js)
    ↓  commits src/data/sheets/pramaan-library.json + src/data/pramaan-library-photos.json + public/assets/images/pramaan-library/
PramaanLibrary / PramaanLibraryDetail (/pramaan/resource-centre) and AblHome's counts (/pramaan) — import the snapshot at build time
```
No page reads a Sheet in the browser. (The former live read — `useABLData` → Apps Script — was retired on 2026-11-19; archived in git tag `archive/pramaan-live-read`.) See §8.

**4 — Publications pipeline (second Sheet integration, same pattern)**
```
Google Sheet "TIDE THRIvE Publications (Responses)" (Google Form responses; private, has an "Email address" column)
    ↓  apps-script/publications/Code.gs — token-gated export/fetchImage only; rows answered TIDE/THRIvE with a title;
    ↓  never reads the email column; Timestamp → anonymous id P-<10 hex> (rows typed in by hand without a Timestamp:
    ↓  id from org + title + date); "www.…"/"doi.org/…" links get https:// added; optional "Hide from website" column
.github/workflows/sync-publications.yml → scripts/sync-publications.js (+ scripts/lib/publications-snapshot.js, scripts/lib/snapshot-core.js, scripts/lib/sync-runner.js)
    ↓  thumbnails: scripts/lib/publications-images.js (trim borders; TIDE covers whole; THRIvE kept between 3:4 and 16:9) → 2 WebPs + pixel sizes in the manifest
    ↓  commits src/data/sheets/publications.json + src/data/publications-photos.json + public/assets/images/publications/
TidePublications (/tide/publications, TIDE rows) and ThrivePublications (/thrive/publications, THRIvE rows) — import the snapshot at build time
```
Live since 2026-11-20 (first sync commit `f524770`); the snapshot and photo manifest are written only by the sync bot (`content:validate` requires both files to exist). See §8 "Publications".

**5 — Partners pipeline (third Sheet integration, same pattern)**
```
Google Sheet "TIDE/THRIvE Partners (Responses)" (Google Form responses; columns "Column 2" / "Notes for …" are internal)
    ↓  apps-script/partners/Code.gs — token-gated export/fetchImage only; rows with a Type of partner and a Name;
    ↓  reads only Type, Priority, Name, Website, Logo (+ Timestamp → anonymous id PA-<10 hex>); optional "Hide from website"

    ↓  logos: scripts/lib/partners-images.js (trim margins, transparency kept, never cropped, ≤ 400×400 WebP + pixel size in the manifest)

```
Sync not connected yet: a static preview is published (owner decision, 2026-11-23) until the owner's setup. See §8 "Partners".

**6 — Social Changemakers pipeline (fourth Sheet integration, same pattern)**
```
Google Sheet "Social Changemakers' Fellowship Completion Form (Responses)" (Form responses; two email columns never read)
    ↓  apps-script/social-changemakers/Code.gs — token-gated export/fetchImage only; rows with a Name and an SCF Batch
.github/workflows/sync-social-changemakers.yml → scripts/sync-social-changemakers.js (+ scripts/lib/social-changemakers-snapshot.js, -images.js, snapshot-core.js, sync-runner.js)
    ↓  commits src/data/sheets/social-changemakers.json + src/data/social-changemakers-photos.json + public/assets/images/social-changemakers/
SocialChangemakers (/education-for-harmony/social-changemakers) — imports the snapshot at build time
```
Live since 2026-11-23. See §8 "Social Changemakers".

**Build output.** `npm run build` = `vite build` + `scripts/prerender.mjs`: headless Chromium (Playwright) loads every address in `src/config/siteRoutes.js` (17 primary pages + one per Resource Centre row; the sitemap leaves out Social Changemakers) from `dist/` and saves the rendered HTML, plus forwarding pages for `REDIRECT_ROUTES`, `404.html` and `llms-full.txt` (§10).

### Routing

`src/routes.js` exports `ROUTES` (24 `[path, Page]` pairs, 22 lazy-loaded page components) and `preloadPage(pathname)`; `src/App.jsx` maps them to `<Route>`s. `src/main.jsx` removes the prerendered `<title>` and `[data-prerender]` head tags, preloads the current page's code, then renders (no hydration: the app replaces the prerendered DOM). Public addresses for the build are listed separately in `src/config/siteRoutes.js` (`PRIMARY_ROUTES`, `RESOURCE_ROUTE`, `REDIRECT_ROUTES`); `src/test/routing/siteRoutes.test.jsx` keeps the two lists equal. `BrowserRouter` (`basename={import.meta.env.BASE_URL}`) wraps everything — clean URLs, no `#`. `Layout` (skip link + Header + Footer) wraps every route; each page chunk is loaded with `lazyPage()` (`src/utils/reloadOnStaleChunk.js`: React.lazy that, when a page's file is gone after a deploy, reloads once and keeps the loader up instead of showing the crash screen; a second failure within 10 s is re-thrown) behind a `Suspense` fallback that shows `CreativeLoader` only after 200 ms (`useDelayedVisible`). `src/components/ErrorBoundary.jsx` wraps the whole app (outside the Router and `HelmetProvider`), and `Layout` wraps each page in a second `<ErrorBoundary inline>` inside `<main>` (since 2026-11-24, audit P5): a crash in one page shows the same screen as a `<div>` while the header and footer stay, and moving to another page clears it. On a render crash it shows a friendly screen (heading/body/button labels from `content/shared/error.yaml`, a reload button and a plain `<a>` home link) and logs the error to the console; the error message and stack are rendered only when `import.meta.env.DEV`. `MotionConfig reducedMotion="user"` makes all Framer animations respect the OS setting.

| Group | Count | Routes |
|---|---|---|
| Primary | 18 | `/`, `/about/{why-tide,past-programs,our-team,our-partners}`, `/tide/publications`, `/education-for-harmony`, `/education-for-harmony/mccx`, `/education-for-harmony/social-changemakers` (not in any menu), `/pramaan`, `/pramaan/resource-centre`, `/pramaan/resource-centre/:id`, `/pramaan/contribute`, `/get-involved/{volunteer,donate}`, `/thrive`, `/thrive/publications`, `/contact` |
| Redirect | 3 | `/about/publications` → `/tide/publications` (the TIDE page's address until 2026-11-20; `TidePublicationsRedirect`); `/pramaan-library`, `/pramaan-library/:id` → `/pramaan/resource-centre(/:id)` (the Resource Centre's former address; `LibraryRedirect`). Both keep the query string |
| System | 3 | `/coming-soon`, `/404`, `*` (the last two both render `NotFound`) |

The 16 routes that predated the restructure (`/about/our-results`, `/projects/*`, `/get-involved/{work-with-us,mccx}`, `/resources/*`) were **removed outright** by owner decision, with no redirects: their pages, YAMLs and generated JSON are gone, and those URLs now fall through to `*` and render `NotFound`. `src/test/routing/removedRoutes.test.jsx` renders the real `<App />` at each removed path and asserts the NotFound page (plus a control that a live route does not). `OrganizeMCCx` is served only at `/education-for-harmony/mccx`. `git checkout a4126d1 -- <path>` recovers the old files.

## 3. Design System

### Colour tokens

| Tailwind class | Hex | Usage |
|---|---|---|
| `text-primary` / `bg-primary` | `#1E6BAA` | Buttons, links, heading accents |
| `bg-primary-mid` | `#2E85C7` | Gradient buttons (paired with `primary-dark`) |
| `bg-primary-dark` | `#15538A` | Gradient buttons, hover states |
| `bg-primary-light` | `#D4EBF8` | Chip backgrounds, hover tints |
| `bg-primary-faint` | `#EEF6FC` | Subtle backgrounds |
| `text-accent` / `bg-accent` | `#F59E0B` | **Backgrounds/dark-backdrop text only** — see accessibility note below |
| `text-accent-deeper` | `#B45309` | Accent-colored **text or icons on a light background** (cream/white) |
| `bg-accent-dark` | `#D97706` | Gradient buttons, hover states |
| `bg-navy` | `#0D2137` | Dark section/card backgrounds (Footer, EFH, WhyTide vision, Volunteer dark sections). **Not** `PageHero` — that banner is the literal `bg-[#1c314d]` |
| `text-tide-text` | `#0D1F3C` | Body copy |
| `text-tide-muted` | `#5A6A7E` | Secondary labels, captions — passes 4.5:1 on `tide-bg`/white, but NOT on `bg-primary-light` (4.49:1, borderline) |
| `text-tide-mutedOnLight` | `#4D5C6F` | Same role as `tide-muted`, but for text sitting on `bg-primary-light` or `bg-tide-border` specifically |
| `bg-tide-bg` | `#FDFCF9` | Page section backgrounds |
| `bg-tide-subtle` | `#F0EDE8` | Input fields, card inner areas |
| `border-tide-border` | `#E2DDD7` | Card and input borders |

Full token map (incl. `deeper`/all shade variants): `tailwind.config.js`. If this table ever disagrees with that file, trust `tailwind.config.js`. The `<meta name="theme-color">` in `index.html` is `#1E6BAA` (same as `primary`).

**Accessibility note on `text-accent` (2026-06-22 audit):** `#F59E0B` is too light to use as foreground text/icon color on a light background — only 2.09:1 on `tide-bg`, 2.15:1 on white, failing even the relaxed 3:1 "large text" threshold. It works well (5.9–7.6:1) on dark backdrops (navy footer, dark hero overlays, `bg-navy` cards) precisely because it's light — use `text-accent-deeper` instead whenever accent-colored text/icons sit on a light background. Same logic applies to the `text-tide-muted` → `text-tide-mutedOnLight` swap on light-blue chip backgrounds. Don't pattern-match the wrong fix from a different background context — check what's actually behind the text first.

### Typography

| Tailwind class | Font | Usage |
|---|---|---|
| `font-display` | Playfair Display | Headings h1–h3, card names, section titles |
| `font-body` | Plus Jakarta Sans | All body text, labels, inputs, buttons |

`font-display` and `font-body` are single combined stacks in `tailwind.config.js` (Playfair/Plus Jakarta Sans first, then the Noto Devanagari and Gujarati families as glyph fallbacks), and `index.html` loads those Noto families from Google Fonts. They exist so glyphs that appear in data still render: Gujarati for the Gujarati titles in Pramaan resource data; the owner chose to keep Devanagari as a fallback too. Nothing switches fonts by language, there is no CSS keyed on `<html lang>`, and `lang` stays `en`.

### Keyboard focus ring

The global `:focus-visible` rule in `src/index.css` draws a 2px outline in the brand blue (`theme('colors.primary.DEFAULT')`, `#1E6BAA`) with a 2px offset, plus a 2px white `box-shadow` band, so the ring stays visible on the dark navy sections (brand blue alone is only about 2.9:1 there). A few components (e.g. the `PhotoStrip` tiles and the Resource Centre filters) opt out with `focus:outline-none` and draw their own Tailwind `ring` instead.

### Accessibility helpers (audit P2, 2026-11-24)

- **Scroll padding:** `html { scroll-padding-top: 5.5rem }`, and `150px` when the page has a `[data-sticky-subnav]` bar (`AblNavBar` — `"tall-only"`, back to 5.5rem under `max-height: 500px` where it stops sticking — and `PartnerIndexBar`). Keyboard focus, `#anchors` and `scrollIntoView` stop below the bars (WCAG 2.4.11/2.4.12). Sections no longer carry `scroll-mt-*`; don't add it back (it would add to the padding).
- **`.hit-44`** (`src/index.css`): an invisible `::after` that makes a small control's pointer target 44 x 44 px (2.5.5 AAA) without changing its look. The control must be positioned and have room around it (neighbours' areas must not overlap); used on header items, footer links + Donate, Pramaan tabs, Resource Centre sort controls, Donate copy buttons, THRIvE area links.
- **`useLoopWindow(active)`** (`src/hooks/`): true for `LOOP_BUDGET_MS` (5 s, `motionPresets.js`) after `active` first turns true, then false for good. Every decorative loop that starts by itself uses it or an equivalent (CSS `[animation-iteration-count:5]` on 1 s animations, a single beat instead of an interval), WCAG 2.2.2. Exceptions: the loader (exempt) and the SCF intro dot (owner decision 2026-11-23; open owner question).
- **`LangText` / `utils/scriptLang.js`:** wraps Gujarati-script runs of Sheet text in `<span lang="gu">` (`textLang()` for `alt`); used for Resource Centre titles. Devanagari alone is left unmarked (language not knowable from the data).
- **`[data-a11y-decorative]`:** aria-hidden, purely decorative text excluded from the axe contrast check (e2e + `a11y-audit.cjs`); currently only the faint "01"–"04" on `/thrive`.

### Scroll animation pattern

Every scroll reveal on the site uses `src/utils/motionPresets.js` (motion rules, 2026-11-24):
```jsx
import { fadeUp, revealDelay, REVEAL, EASE_OUT } from '../utils/motionPresets'

<motion.div {...fadeUp()} />       // 10px rise, 0.45s, fast-start curve EASE_OUT, once, starts 32px into the window
<motion.div {...fadeUp(0.1)} />    // argument = delay; older delays are scaled ×0.4 and capped at REVEAL.maxDelay (0.2s)
transition={{ delay: revealDelay(i) }} // a row: 0.05s apart, the whole row done within 0.2s
```
The rules (keep them): **nothing on the first screen waits to appear** — `PageHero` and the homepage banner text are static; page changes fade in over 0.2s with no exit wait and the first page of a visit has no fade (`Layout`, `AnimatePresence initial={false}`). Things coming in start fast and settle (never the slow-start `[0.4, 0, 0.2, 1]`); small distances (≤ 12px); one fade per group rather than one per element; no bouncy springs on content (the pinned "print" frames keep their own swing, with short delays). **Count-ups: at most one per page, only the page's main figure**, via `CountUpText` — homepage: lives impacted; Partners: the partner total; Pramaan: the number of resources. Never a year, a phone number, a small number (< 100, shown as is) or a number inside a sentence. `<MotionConfig reducedMotion="user">` in `App.jsx` drops movement under "reduce motion".

### Non-serialisable values (Tailwind + icons in YAML)

Tailwind classes must appear as complete strings in source — never construct them dynamically. Icons are React components and can't be JSON. The pattern:

1. Store a key string in YAML: `iconKey: "BookOpen"`, `colorKey: "blue"`
2. Define a lookup map in the component:

```jsx
const ICONS = { BookOpen: <BookOpen className="w-5 h-5" />, Users: <Users className="w-5 h-5" /> }
const COLOR_MAP = {
  blue:    'bg-blue-50 text-blue-700 border-blue-200',
  emerald: 'bg-emerald-50 text-emerald-700 border-emerald-200',
}
// Usage: {ICONS[item.iconKey]}   COLOR_MAP[item.colorKey]
```

### Button

```jsx
<Button
  variant="primary"         // primary | secondary | accent | ghost | white
  size="md"                 // sm | md | lg
  to="/internal/path"       // renders as <Link> (React Router)
  href="https://external"   // renders as <a>
  external                  // with href: adds target="_blank" rel="noopener noreferrer"

```

With neither `to` nor `href` it renders a `<button>`; extra props are spread onto the element. `href` alone does **not** open a new tab — pass `external` for that.

### PageHero

```jsx
<PageHero
  badge="Section · Subsection"    // small label above the title
  title="Page Title"              // h1
  subtitle="Optional description"
>{/* optional children, rendered under the subtitle */}</PageHero>
```

Props are exactly `{ badge, badgeClassName, title, subtitle, children, aside }`; `aside` is an optional node placed to the right of the text on large screens (below it on small ones), used by `/pramaan` for the promo video. `badgeClassName` replaces the badge's default `bg-white/15 text-white/90 border-white/25` colour classes; the resource detail page passes the type's `heroBadge` so the banner pill wears the type colour. Background is the literal `bg-[#1c314d]` plus a texture image. There is no `gradient` prop (it used to be passed, and ignored, by 10 pages; those were removed) — don't add one. The header is fixed and transparent with white text over the hero, so inner pages need a `PageHero` (or an equivalent dark top section) first, before `<AblNavBar>` or any content.

### SeoHead

```jsx
<SeoHead
  title={data.meta.seoTitle}
  description={data.meta.seoDescription}
  path="/get-involved/volunteer"           // required; canonical = site.url (site.yaml) + path
  breadcrumbs={[
    { name: site.breadcrumbs.home, path: '/' },
    { name: site.breadcrumbs.getInvolved },                        // no path → no `item` in the JSON-LD
    { name: data.meta.breadcrumbName, path: '/get-involved/volunteer' },
  ]}                                        // import site from '../../data/site.json'
  noindex                                   // optional, default false
  ogImagePath="/some/image.png"             // optional; appended to window.location.origin WITHOUT the base path
/>
```

Every page except `ComingSoon` and `NotFound` (which use `<Helmet>` directly with `noindex`) and the redirect components `LibraryRedirect` / `TidePublicationsRedirect` (no head tags; the build writes their noindex forwarding pages) renders `SeoHead`. It emits title, description, canonical, og:*, twitter:*, optional `robots noindex`, and a BreadcrumbList JSON-LD block (a breadcrumb without `path` omits `item`; written with `jsonLdText`, because a resource page's last step is Sheet text). `SITE_URL` and the default og:image (`site.logo` under `BASE_URL`) come from `site.json`. Breadcrumb names are not hardcoded: parent steps come from `content/shared/site.yaml` `breadcrumbs.*` and each page's own last step is `meta.breadcrumbName` in its YAML (`PramaanLibraryDetail` uses the resource name). Head tags are rendered by React 19 (react-helmet-async v3 hands `<title>`/`<meta>`/`<link>` to React's own hoisting; the BreadcrumbList `<script>` stays in the body). The build prerenders each page with them (`scripts/prerender.mjs` marks them `data-prerender`); `src/main.jsx` removes those and every `<title>` before the app renders, because React added a second `<title>` instead of reusing the HTML's (seen on staging 2026-11-24). `site.yaml` `indexable: false` adds `noindex` on every page. `ogImagePath` / the default og:image use `window.location.origin` (the prerender runs at the real origin, see §10 Base path). `index.html` has no static description/canonical, but its `<title>`, `og:site_name` and the NGO/WebSite JSON-LD are generated from `site.yaml` by `scripts/siteDataPlugin.js`.

### Lightbox (gallery — for non-ABL pages)

`Lightbox` is a controlled, presentational component — the page owns the open/index state (usually through `useLightbox(count)`):

```jsx
import { AnimatePresence } from 'framer-motion'
import { useLightbox } from '../hooks/useLightbox'
import Lightbox from '../components/ui/Lightbox'

const images = [{ src: 'assets/photo.jpg', label: 'Caption' }]   // or plain strings
const lb = useLightbox(images.length)        // count is REQUIRED
// Open: lb.openLightbox(index)

<AnimatePresence>
  {lb.isLightboxOpen && (
    <Lightbox
      images={images}                         // (string | { src, alt?, label? })[]
      currentIndex={lb.lightboxIndex}
      onClose={lb.closeLightbox}
      onPrev={lb.prevLightbox}
      onNext={lb.nextLightbox}
      onGoTo={lb.openLightbox}                // optional; without it, clicking a dot CLOSES the lightbox
    />
  )}
</AnimatePresence>
```

`item.alt || item.label` is used as the image `alt` and the dialog's `aria-label`; **no caption is rendered under the image anywhere on the site** (owner decision) — don't add one. Pass `translucent` for a see-through, blurred backdrop (the `/pramaan` gallery) instead of the near-opaque default. The tint and blur ease in on their own layer and the controls fade separately: **never fade a parent that holds a `backdrop-filter`** (it pops at full strength on the first frame), and keep the picture `relative z-[1]` so the positioned backdrop does not paint over, and blur, it. `Lightbox` applies `imgSrc()` to every `src` itself — **do not pre-apply `imgSrc`** (see §11). Escape closes, ←/→ navigate, body scroll is locked (`useModalBehavior`), focus is trapped (`useFocusTrap`), and the dot strip shows for 2–20 images. Its aria-labels come from `content/shared/ui.yaml` (`lightbox.*`).

For a click-to-zoom photo grid, pair `useLightbox(count)` with `<AnimatePresence>{isLightboxOpen && <Lightbox …/>}</AnimatePresence>` — `src/components/abl/PhotoStrip.jsx` (the `/pramaan` photo strip) is the working example. For multiple galleries on one page, use separate `useLightbox(count)` instances with distinct names.

### Pagination

```jsx
<Pagination
  total={filtered.length}  // total matching resources
  page={page}
  onChange={handlePageChange}
  perPage={LIBRARY_PAGE_SIZE}  // optional, defaults to LIBRARY_PAGE_SIZE (9, src/config/library.js)

Renders nothing when there's only one page. ## 5. Hook Reference

### useLightbox

```js
const { isLightboxOpen, lightboxIndex, openLightbox, closeLightbox, prevLightbox, nextLightbox }
  = useLightbox(count)          // count = number of images — REQUIRED
// openLightbox(index) — open at a specific image
// prevLightbox() / nextLightbox() — cycle with wrap-around (modulo count)
```

`lightboxIndex` is `null` while closed. Calling it without `count` makes prev/next produce `NaN`. `PhotoStrip.jsx` is the working example.

### useModalBehavior

```js
useModalBehavior({ active = true, onClose, onKeyExtra, target = 'document' })
```

Shared overlay behaviour: while `active` is truthy, Escape calls `onClose`, any keydown is also forwarded to `onKeyExtra(e)` (e.g. Lightbox arrow keys), and `document.body` scrolling is locked; cleanup resets `body.style.overflow` to `''`. `target` (`'window'` | `'document'`) chooses where the listener lives (Lightbox uses `window`, `ImageLightbox`/`VideoLightbox` use `document`). Keep `onClose`/`onKeyExtra` referentially stable (`useCallback`) — a new identity re-registers the listener. Used by `Lightbox`, `ImageLightbox`, `VideoLightbox`; pair it with `useFocusTrap`, declared first.

### useFocusTrap

```js
const containerRef = useFocusTrap(active = true)   // attach containerRef to the dialog element
```

On activation stores `document.activeElement`, focuses the first usable focusable child (selector `button, a[href], iframe, input, select, textarea, [tabindex]:not([tabindex="-1"])`, skipping disabled, `tabindex=-1`, `aria-hidden`/`inert` and unrendered ones); Tab/Shift+Tab wrap at the ends and also from a focused element outside that list (e.g. a heading focused on open); a `focusin` guard pulls focus back if it lands outside (Tab out of a cross-origin video iframe); open traps form a stack and only the topmost acts (VideoLightbox over FellowProfile). Tested in `src/test/hooks/useFocusTrap.test.jsx`. Escape pressed while focus is inside a cross-origin player iframe never reaches the page (browser limit): Shift+Tab back to Close. It restores focus on deactivation/unmount (with `preventScroll`, so closing a dialog never scrolls or glides the page). For a conditionally *mounted* dialog, the default `true` is right; for an always-mounted one pass the open condition.

### useDelayedVisible

```js
const show = useDelayedVisible(active, delayMs = 200)
```

True only if `active` stays true for longer than `delayMs` — gates loading UI so fast loads never flash it (used for the route `Suspense` fallback).

### useSidebarFits

```js
const [sidebarRef, sticky] = useSidebarFits(top)   // top = sticky offset in px, matching the top-[…] class
```

`sticky` is true only while the element's height + `top` + 16px fits in the window (re-checked with a `ResizeObserver` and on resize), so a tall listing sidebar scrolls with the page instead of getting an inner scrollbar. Used only by `PramaanLibrary` (`top` 130); the Publications pages have no sidebar.

### usePublicationControls (`src/hooks/usePublicationControls.js`)

Used by `TideCollection` and `ResearchArchive`.
- `usePublicationQuery({ rows, shortcutKey, undatedHeading, searchChipTemplate })` → `{ params, change, set, clearAll, input, setInput, inputRef, options, filtered, terms, chips, active, resultsRef }`: everything both pages share about search + filters, kept in the URL query string. `change(next, { focus })` replaces the query (with `focus: true` it also moves focus to the results line); `set(patch)` patches it and returns to page 1.
- `useDebouncedSearch(urlValue, commit, delay = 150)` → `[input, setInput]`: the box updates at once; `commit(value)` runs after a 150 ms pause in typing; a change of the URL value from elsewhere (Clear all, a chip, Back) is copied into the box, but the URL catching up to the box's own last commit is not (the router applies URL changes in a transition; copying back would drop characters typed meanwhile). Keep `commit` stable (`useCallback`).
- `useFocusShortcut(key, ref)` — pressing `key` (e.g. `/`) anywhere except a form field or editable element focuses `ref` (does nothing for an empty key).
- `focusResults(el)` — scrolls `el` into view (instant under reduced motion) and focuses it without scrolling again.

## 6. Utility Reference

### imgSrc.js

```js
import { imgSrc } from '../utils/imgSrc'

imgSrc('/assets/images/foo.jpg')   // → BASE_URL + 'assets/images/foo.jpg'
imgSrc('assets/images/foo.jpg')    // → same
imgSrc('https://…')                // → returned as-is (also data: URLs)
imgSrc('')                         // → ''  (null/undefined too)
```

Use it for any image path that comes from YAML/JSON so it works on both `/` (dev) and `/tide-testing/` (GitHub Pages). **It is not idempotent** — see the gotcha in §11. Some files (Home, Header, Footer, PageHero, SeoHead, ErrorBoundary) instead build `${import.meta.env.BASE_URL}${path}` by hand; that only works because `yaml-to-json.js` strips the leading `/` from `/assets/...` values.

### imagePlaceholder.js

`installImagePlaceholder(doc = document)` is called once in `src/main.jsx` before the app renders. It adds one capturing `error` listener on the document (image `error` events don't bubble) and, for any `<img>` that fails to load, drops `srcset` and sets `src` to the placeholder: `imgSrc(site.placeholderImage)`, where `placeholderImage` is `/assets/images/shared/placeholder.svg` in `content/shared/site.yaml`. An image opts out with the `data-no-placeholder` attribute (`abl/DriveImage.jsx` does, because it draws its own `<BookOpen>` fallback); the placeholder's own URL is skipped so a missing placeholder can't loop. It returns an uninstall function (used by `src/test/utils/imagePlaceholder.test.js`). Because it's global, don't add per-image `onError` handlers for the same purpose.

### motionPresets.js

`fadeUp(delay = 0)` → motion props (10px, 0.45s, `EASE_OUT`, once, margin `REVEAL.margin`; delay ×0.4, capped at `REVEAL.maxDelay`); `revealDelay(i)` → a row's stagger; `REVEAL` and `EASE_OUT` for one-off animations. See §3 "Scroll animation pattern".

### config/abl.js and config/library.js

`config/abl.js` exports the resource-type tables for the Pramaan screens: `TAB_STYLE_MAP` and `getTabStyle(tab)` (returns the map entry, falling back to `_default` for unknown types), and `TYPE_COLORS` / `getTypeColors(tab)`: the single class palette per colour name (`badge`, `eyebrow`, `solid`, `soft`, `tint`, `selectedTile`, `poster`, `heroBadge`, `tileHover`, `cardHover`, `titleHover`) that `ResourceTypeBadge`, the `/pramaan` type cards and the Resource Centre's badges, filter tiles and cards all read, so a type is the same colour everywhere. ## 7. CMS Pipeline

### Commands

```bash
npm run content:sync       # YAML → JSON (also runs automatically via predev/prebuild)
npm run content:validate   # YAML syntax + image path checks + site.yaml consistency (see below)
npm run content:bootstrap  # Writes starter shared/navigation.yaml + footer.yaml ONLY if absent. Does not touch pages; rarely needed.
```

### What `scripts/yaml-to-json.js` does

- Walks `content/pages/**` and `content/shared/**` (`*.yml|*.yaml`) and writes `src/data/<basename>.json`. The output is **flat**: directory names are dropped, so two YAMLs with the same basename (e.g. one in `pages/`, one in `shared/`) silently overwrite each other. It is run from the repo root (paths resolve from `process.cwd()`).
- Any string value starting with `/assets/` has its leading `/` stripped (so `/assets/images/x.jpg` → `assets/images/x.jpg`); other leading-slash values (routes, `mailto:`) are untouched.
- Fails fast on invalid YAML (non-zero exit → blocks `dev`/`build`, and CI). It does **not** delete JSON for a YAML you removed (the stale file stays importable), and has no schema/required-field checks. Only `*.yml|*.yaml` are read, so `content/shared/llms.txt` is ignored.
- `src/data/*.json` is committed, but regenerated on every dev/build — never hand-edit it.

### What `scripts/validate-content.js` checks (and doesn't)

Walks all of `content/`; a YAML parse error is an error (exit 1), a missing image is only a warning (exit 0). Every string value (object field or list item, any key) that is a local file path is checked: it starts with `/assets/` or `assets/`, or ends in an image/media extension (`png jpg jpeg webp avif gif svg ico mp4 webm pdf`), and is not http(s)/`mailto:`/`tel:`/`data:`. A missing file, or a bare file name with no folder, is a warning (since 2026-11-24, audit P1; before that only a fixed list of keys with a leading `/` was checked). It does not check hrefs/routes.

**Consistency errors (exit 1):** via `scripts/contentConsistency.js`, every string in every YAML (plus the `llms.txt` template) is scanned. Any email address that differs from `site.yaml` `email` is an error, and so is any lives-impacted total (a `NN,NNN+` / `NNNNN+` figure in the same sentence as "lives / people / impacted / changed", or a bare figure whose sibling fields say so) that differs from `site.yaml` `livesImpacted`. Other metrics such as "15,000+ students" are deliberately not flagged. To change the email or the figure, edit `site.yaml` and then every page string that quotes it. CI (`deploy.yml`) runs the validator before building, so an error stops the deploy. It also checks the Resource Centre snapshot (`checkLibrarySnapshot()`: shape, unique ids, allowlisted fields only, no e-mail addresses, `meta.total`, photo manifest paths/files), the Publications snapshot (`checkPublicationsSnapshot()`: the same checks plus `org` TIDE/THRIvE, `date` `YYYY-MM-DD` or null, `fields` a list, http(s)-only `link`/`photoUrl`, `meta.counts` per org), the Partners snapshot (`checkPartnersSnapshot()`: shape with `section: "partners"`, id/name/type present, unique ids, allowlisted fields, http(s)-only `website`/`photoUrl`, no e-mail address, `meta.total`, logo paths inside `assets/images/partners/` with their files) the Social Changemakers snapshot (`checkSocialChangemakersSnapshot()`) and `abl-contribute.yaml` `formUrl` (empty → warning; anything but a Google Forms link → error).

### File naming convention

```
content/pages/about-our-team.yaml   →   src/data/about-our-team.json
content/shared/navigation.yaml      →   src/data/navigation.json
content/shared/footer.yaml          →   src/data/footer.json
```

Shared files (`content/shared/`): `navigation` (header menu, logo, skip-link/aria labels, Donate CTA labels), `footer`, `common` (micro-copy reused across pages: `step`, `viewLinkedIn`), `ui` (Lightbox aria-labels and the Pramaan photo/video viewer labels), `loader` (CreativeLoader messages), `error` (ErrorBoundary crash screen), `not-found`, `coming-soon`, `site` (site-wide facts — see §1 "Site-data pipeline"; `breadcrumbs.*` are the parent steps of every breadcrumb trail). Pages import the JSON for their YAML and read it directly:

import SeoHead from '../components/ui/SeoHead'

        path="/page-name"

// Sub-directory page  (src/pages/about/WhyTide.jsx)

```

**Never type visible English text into JSX.** Every string must come from `data.*` / `common.*` / `ui.*` so non-developers can update it via YAML. Dynamic strings use `{token}` placeholders in YAML (`"Grade {n}"`, `"{name} — TIDE Pramaan"`) that code fills in with `.replace('{n}', …)` or a small `fill()` helper — see `pramaan-library.yaml` (`detail.titleTemplate`, `page.showResultsTemplate`), `ui.yaml` (`goTo`), `not-found.yaml` (`seoTitleTemplate`).

### Lint guard (`react/jsx-no-literals`)

`eslint.config.js` makes `react/jsx-no-literals` an **error** in `src/pages/**/*.jsx` and `src/components/**/*.jsx` (`noStrings: false`, `ignoreProps: true`; allowed bare strings are punctuation/glyphs: `— – · → ↗ … | / - : . , & + ( ) % " ' “ ” ’`). Text typed straight into JSX therefore fails `npm run lint`. A second rule in the same block, `no-restricted-syntax` with the `CMS_TEXT_SELECTORS` list (2026-11-24), fails on a word (any string with a letter) typed into a text prop — `alt, title, placeholder, label, aria-label, aria-description, aria-roledescription, aria-valuetext, aria-placeholder, badge, subtitle, heading, eyebrow, caption, tooltip, description` — directly, in `{…}`, in a `?:` / `||` / `&&` / `+`, or in a template literal; and on the same in JSX children (`{'Text'}`, `{a ? 'Text' : b}`, `` {`${n} results`} ``). Strings with no letter (`alt=""`, `` `${a}: ${b}` ``) pass. Tests: `src/test/scripts/cmsGuard.test.js`. Still not caught: text built in plain JS away from the JSX (a `const label = '…'` used later), and a string used as a lookup key inside a text prop's ternary would be a false positive (compute the key outside the JSX). JSON-LD and breadcrumb names are no longer hardcoded (they come from `site.yaml` / `meta.breadcrumbName`). CI runs lint too (a failure stops the deploy); run it locally first. Also see `.claude/skills/cms-integrity/SKILL.md`.

### Image paths in YAML

Images live in `public/assets/`. Both spellings work because the sync script strips a leading `/` from `/assets/…` values, and the repo overwhelmingly uses the leading-slash form (≈165 values vs 5 without):
```yaml
photo: /assets/team/jane-smith.jpg   # dominant style
photo: assets/team/jane-smith.jpg    # also works (checked by the validator since 2026-11-24)
```
The one hard rule: components must pass YAML image values through `imgSrc()` (or prefix `import.meta.env.BASE_URL`), never use them raw (§6, §11). `CONTENT-GUIDE.md` tells editors the leading-slash form.

### Navigation subItems (flyout menus)

In `content/shared/navigation.yaml`, adding `subItems` to a dropdown child turns it into a nested group (a third menu level) — no JSX changes needed. The group itself is a button, not a link (a `to` on it is not used); each sub-item is `{ label, to }`. In use since 2026-11-20 for About Us → Our Publications:

```yaml
- label: "About Us"
  children:
    - label: "Our Publications"
      desc: "Annual reports, research & events"
      subItems:
        - label: "TIDE Publications"
          to: "/tide/publications"
        - label: "THRIvE Publications"
          to: "/thrive/publications"
```

Desktop: a sub-menu opening to the right (`SubGroup` in `Header.jsx`, keyboard in §4). Mobile: a collapsible list under the parent item (its button is highlighted when it holds the current page). A page may appear in two menus (THRIvE Publications is also in the THRIvE Research Centre dropdown); `navActive.js` highlights one top-level entry.

### GitHub Actions

**`.github/workflows/deploy.yml`** — triggered by push to `main` and manual `workflow_dispatch`:

## 11. Gotchas & Constraints

### BrowserRouter on a static host (GitHub Pages)

All internal links must use `<Link to="...">` from React Router, never `<a href="...">`:
```jsx
// Wrong
<a href="/about/our-team">Team</a>

// Correct
<Link to="/about/our-team">Team</Link>
```

Plain `href` triggers a real page navigation instead of client-side routing — slower, and on first load `index.html`'s inline script has to run the redirect-restoration logic again.

**Since 2026-11-24 every public route is a real file** (`scripts/prerender.mjs`): GitHub Pages answers `/about/why-tide` from `about/why-tide.html` with HTTP 200 (verified on the live host for `/404` → `404.html`), and a path that is also a folder (`/pramaan`) gets `pramaan.html` + `pramaan/index.html` (which of the two GitHub Pages picks was not verified). `404.html` is the prerendered NotFound page; the app renders the right route on top of it for addresses with no file. The paragraph below describes the old trick, which is now only a fallback for old `/?/path` links. GitHub Pages serves static files only — there's no server-side rewrite for deep routes. Before, the site used the standard `404.html`-redirect trick: a hard reload or direct link to e.g. `/pramaan/resource-centre?type=worksheet` gets served `public/404.html`, which redirects to `/?/pramaan/resource-centre&type=worksheet`; `index.html`'s inline script then decodes that back into the real path via `history.replaceState` before React mounts. **If you touch either script, verify the query-string case specifically** — a previous bug here joined the restored path and query with `&` instead of `?`, which silently produced a malformed URL (no error, just a blank page) for any route with query params on a hard reload.

### `imgSrc()` is not idempotent

`imgSrc(path)` prepends `BASE_URL` to anything that isn't already `http(s):`/`data:`. On GitHub Pages `BASE_URL` is `/tide-testing/`, so applying it to an already-resolved path yields `/tide-testing/tide-testing/...` (a 404). In dev `BASE_URL` is `/`, which hides the bug completely.

- `Lightbox` applies `imgSrc` to every image `src` themselves — pass **raw YAML paths** into them.
- To check a change: `GITHUB_ACTIONS=true npm run build && GITHUB_ACTIONS=true npm run preview`, then open `/tide-testing/…` (next section).

### Previewing the base-path build locally

- `vite preview` must also run with `GITHUB_ACTIONS=true` (PowerShell: `$env:GITHUB_ACTIONS='true'; npx vite preview`). Without it the preview serves base `/`, answers every `/tide-testing/*` request with the index HTML, the JS files load as HTML and the page is blank — not a site bug.
- `vite preview` answers HTTP 200 for every path, so it can't show GitHub Pages' 404s or folder redirects. `node scripts/serve-pages.mjs dist /tide-testing/ <port>` mimics Pages: a file `x`, else a folder → 301 to `x/` (then `x/index.html`), else `x.html`, else `404.html` with status 404. So `/pramaan` answers 301 → `/pramaan/` there even though `pramaan.html` exists — what real Pages does in that case is not verified (P3-3, P6-7). The built-site e2e uses it.
- In Git Bash, any `/tide-testing/` argument (to `vite --base` or `serve-pages.mjs`) is rewritten to a Windows path (`C:/Program Files/Git/tide-testing/`) unless `MSYS_NO_PATHCONV=1` is set — every address then answers 404.
- The prerender loads pages at `http://localhost:4173` locally; og:image URLs in a local build therefore point there (CI uses the real origin).

### The app renders over prerendered HTML (no hydration)

`createRoot` replaces the prerendered DOM; anything that reads `document` before React mounts sees the prerendered page. `main.jsx` removes `<title>` and `[data-prerender]` head tags first — don't add hand-written head tags that rely on surviving that. A page that throws in headless Chromium, or logs a console error (e.g. a CSP violation), now stops the build. The built CSP allows only the hashed inline script of `index.html`; script injected at runtime is blocked in `dist/` but not in dev, so check such changes with the built-site e2e.

### Tailwind dynamic class construction is forbidden

Tailwind scans source files for complete class strings. Constructing them at runtime means the class won't be in the CSS bundle:
```jsx
// Wrong — Tailwind won't include bg-blue-50 or bg-emerald-50
const cls = `bg-${color}-50`

// Correct — full strings appear literally
const COLOR_MAP = { blue: 'bg-blue-50 text-blue-700', emerald: 'bg-emerald-50 text-emerald-700' }
const cls = COLOR_MAP[color]
```

This is why all colour maps in components use lookup tables. Tailwind's `content` globs only `index.html` and `src/**`.

### Pramaan data is built in, not fetched

The Resource Centre and the `/pramaan` counts import `src/data/sheets/pramaan-library.json` at build time (and the Publications pages import `src/data/sheets/publications.json` the same way). A Sheet edit reaches the site only through the sync → commit → deploy (minutes, or the next 6-hourly run) — there is no runtime request and no loading state to handle. Don't reintroduce a browser-side Sheet read (the retired `useABLData` pattern; see `docs/SHEET-INTEGRATION-PLAYBOOK.md`).

### A modal's backdrop, scrollbar and caption

- A blurred backdrop is its own layer, faded on its own (see `Lightbox` in §4): fading the parent that holds a `backdrop-filter` makes the blur pop, and a positioned backdrop paints over a non-positioned picture, so the picture needs `relative z-[1]`. If a viewer's photo looks blurry, check this first.
- `html { scrollbar-gutter: stable }` (`src/index.css`) stops the page shifting sideways when a modal locks body scrolling.
- Image previews show **no caption** anywhere on the site.

### The photo strip tells a tap from a drag

`PhotoStrip` captures the pointer on the strip, so a click lands on the container, not the photo. A tap (under ~6px of movement) is detected in `pointerup` from the tile index recorded at `pointerdown`; each photo is also a focusable button for the keyboard, and only keyboard focus (`:focus-visible`) slides the photo to the middle, so a mouse click never makes the photo jump before the viewer opens.

### Header overflow for flyout menus

The `Dropdown` component in `Header.jsx` uses `overflow-visible` so that flyout submenus can render outside the dropdown container. Do not add `overflow-hidden` to the dropdown wrapper or the flyout will be clipped. The header is `position: fixed` at 70px height; `AblNavBar` (`top-[70px]`) and the Resource Centre sidebar (`top-[130px]`) are positioned against that, so changing the header height breaks both.

MY_SECRET=foo          # NOT visible to browser code
VITE_MY_SECRET=foo     # visible via import.meta.env.VITE_MY_SECRET
```

Either `/assets/hero.jpg` or `assets/hero.jpg` works (the sync script strips the leading `/` from `/assets/…`); the repo's dominant style is the leading-slash form; `content:validate` checks both (any key, since 2026-11-24). ### No hardcoded visible text (CMS convention + lint guard)

Never type English into JSX — that bypasses the CMS and makes the text uneditable:

```jsx
// ✓ Correct — CMS-editable
<h1>{data.hero.title}</h1>
<p>{common.step}</p>                                       // shared micro-copy → content/shared/common.yaml

// ✗ Wrong — hardcoded, CMS cannot update it
<p>Click any image to view full screen.</p>             // also fails `npm run lint`
```

- Shared micro-copy goes in `content/shared/common.yaml` (page-agnostic hints/labels such as `step`, `viewLinkedIn`) and component chrome in `content/shared/ui.yaml` (Lightbox and Pramaan photo/video viewer labels). Component-specific text goes in the page/screen YAML (e.g. `pramaan-library.yaml`).
- `react/jsx-no-literals` is an **error** for `src/pages/**` and `src/components/**` (see §7), so bare JSX text fails `npm run lint`; the `no-restricted-syntax` guard beside it also fails on words in text props (`aria-label`, `alt`, `title`, …) and in `{'…'}` / template text. Text assembled in plain JS away from the JSX is still invisible to both — review by hand.
- **Code-side text accepted on purpose (audit P1; leave it):** Sheet *values* matched in code, not shown as labels — `PRIORITY_ORDER` / `LAST_CATEGORIES` (`src/config/partners.js`), `TYPE_ICON_RULES` keywords (`src/config/publications.js`), `LIBRARY_GRADES` and `OWNER_PINNED` (`src/utils/libraryFilters.js`; grade labels come from `pramaan-library.yaml`), the org filters "TIDE" / "THRIvE" in the two publications pages; schema.org type names, key names, easing names, CSS/SVG values, selectors, `{token}` names, the initials stop-words in `partnerFilters.js`; the `en-IN` locale for numbers and dates (month names come from the browser); punctuation joining YAML text (`` `${a}: ${b}` ``); defensive fallbacks shown only when the YAML is empty (`CreativeLoader` "Loading…", `publicationFilters` `'Undated'` default); `lang="en"` and `theme-color` in `index.html`.
- CI runs lint (a failure stops the deploy), but run `npm run lint` before pushing.

### The e-mail and lives-impacted figure live in `site.yaml`

The contact email is `tidefoundation@gmail.com` and the lives-impacted total is `52,500+` everywhere (owner decision). The single source is `content/shared/site.yaml` (`email`, `livesImpacted`); `npm run content:validate` errors on any other email or lives-impacted total in `content/`. Other metrics (e.g. "15,000+ students") are intentionally not flagged.

### Don't put a literal `<title>` in an HTML comment in `index.html`

`scripts/siteDataPlugin.js` fills the page title with `html.replace(/<title>[\s\S]*?<\/title>/, …)`, which replaces the first match — a commented-out `<title>…</title>` earlier in the file would be rewritten instead of the real tag. Likewise keep the `<!-- site-jsonld -->` marker (the plugin throws if it is missing) and don't hand-write JSON-LD in `index.html`.

### Generated files are committed

`src/data/*.json` is generated and git-tracked; it is re-written on every `dev`/`build`. A manual `git add content/` without re-running the sync leaves the committed JSON behind until CI/the next local run regenerates it.

### AnimatePresence requires key prop

Exit animations on conditionally-rendered elements only fire when the child has a stable `key`:
```jsx
<AnimatePresence>
  {isOpen && <motion.div key="drawer" initial={{ x: '-100%' }} ...>...</motion.div>}
</AnimatePresence>
```
